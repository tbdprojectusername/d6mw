# market_data_v3

Isolated canonical data platform for the new MMA market-forecasting model.
It does not import from, write to, or change
`market_forecast_v2/`.

## Durable design

- Existing SQLite databases and capture CSVs are read-only sources.
- Immutable, compressed Parquet partitions are the durable canonical store.
- DuckDB is rebuilt from those partitions and is an ephemeral query artifact.
- Every source file and output partition is hashed.
- Rejected and ambiguous records are retained with reason codes rather than
  silently repaired or deleted.
- Model labels are not generated by this package. Closing-label certification
  is a later gated phase.
- Moneylines and props have separate schemas and storage roots. A prop row can
  never be consumed by a moneyline view through a broad filename pattern.

## Automated jobs

- `market-live-update.yml`: every ten minutes (plus an event-driven trigger),
  builds the latest small market state directly from the newest public capture
  revision. The future model scorer belongs in this job and must record that
  exact source revision.
- `market-data-refresh.yml`: every three hours, canonicalizes and commits
  durable Parquet partitions. It is storage maintenance, not a scoring clock.
- `market-data-health.yml`: every three hours, independent rebuild, tests, and
  health report. A failure opens a deduplicated GitHub issue.
- `market-data-enrichment.yml`: daily UFCStats reference refresh, a bounded
  current-scorecard increment, and timestamped rankings/roster snapshots.
- `market-data-reference-audit.yml`: weekly independent UFC-DataLab stats and
  scorecard import for cross-source validation.

The jobs deliberately never stage files outside this tree.

## Local use

```bash
pip install -r market_data_v3/requirements.txt
python -m unittest discover -s market_data_v3/tests -p "test_*.py"
python -m market_data_v3.src.cli ingest-live --source-dir PATH_TO_CAPTURE_DATA
python -m market_data_v3.src.cli build-current-state --source-dir PATH_TO_CAPTURE_DATA
python -m market_data_v3.src.cli ingest-reference --source greco_ufcstats --source-dir PATH
python -m market_data_v3.src.cli ingest-scorecards
python -m market_data_v3.src.cli capture-snapshots
python -m market_data_v3.src.cli validate
python -m market_data_v3.src.cli build-catalog
```

One-time historical bootstrap is read-only:

```bash
python -m market_data_v3.src.cli bootstrap-fightodds \
  --db C:/Users/cmtub/fightodds_local/fightodds_history.db
python -m market_data_v3.src.cli bootstrap-fightodds-props \
  --db C:/Users/cmtub/fightodds_local/fightodds_history.db
python -m market_data_v3.src.cli bootstrap-scorecards \
  --source-dir PATH_TO_UFC_JUDGING_ANALYSIS \
  --source-revision GIT_SHA
python -m market_data_v3.src.cli backfill-scorecards \
  --start-year 1995 --end-year 2024 --workers 12 --requests-per-second 8
python -m market_data_v3.src.cli reconcile-scorecards
```

It stores unresolved `outcome_no` rather than pretending that the source slot
identifies a fighter. Orientation is a separate canonical overlay.

Historical prop offers are retained as open/current/best/worst endpoint
summaries. Those values are not presented as a tick path or assigned a fake
`available_to_model_at`; true point-in-time prop observations come from the
separate live FightOdds prop feed.

Reference and snapshot tables are also deliberately raw and carry
`feature_eligible=false`. They cannot enter a model until identity,
availability, lagging, and source-agreement transforms are separately tested.
